# PikaPython v2.0.0-rc3 Release Announcement

We are pleased to announce PikaPython v2.0.0-rc3. This release expands the
CPython-aligned module set, strengthens Python import and class behavior, and
keeps the V2 runtime's performance and resource advantages as the primary
product focus.

## New Features and Improvements

- **CPython-aligned modules**: Added and aligned portable, protocol, platform,
  and application modules. CPython behavior is the primary compatibility
  target, with PikaPython V1 behavior used where CPython does not define the
  embedded contract.
- **Composable module projects**: A single Linux module template now combines
  dependencies through `pikapython.yaml`; `bootEntry` selects the Python test
  or application entry and defaults to `main.py`.
- **Python imports**: Pure Python `import` and `from ... import ...` statements
  now compile into Program Images and preserve native and re-exported bindings.
- **Classes and callables**: Imported classes can be used as base classes,
  inherited method overrides dispatch correctly, and callable expressions are
  supported at runtime.
- **Language behavior**: Added `assert` statements, qualified class bases,
  global callable references, triple-quoted imported strings, and chained
  container and text method calls.
- **Agent-ready CLI workflow**: The bundled PikaPython CLI Skill provides the
  preferred workflow for Codex, Claude Code, and other code agents. The CLI can
  also be run directly from the checkout without a pip installation.

## Bug Fixes

- Fixed pure Python modules being rejected by C-binding-only import paths.
- Fixed binding exports and relocations being lost across Python module layers.
- Fixed native `from ... import ...` bindings and private binding module
  selection.
- Fixed imported and qualified class base resolution after parser relocation.
- Fixed class method declarations being omitted from Program Images.
- Fixed dynamic user-method calls after text-method lookup misses.
- Fixed callable references losing their global scope.
- Fixed characters after string literals being dropped during parsing.
- Fixed module edge behavior for binary inputs, text suffix methods, unittest
  overrides, and runtime package dispatch.

## Performance Improvements

- Preserved the register runtime fast path while adding module and callable
  syntax support.
- Optimized positive integer modulo on the register execution path.
- The final syntax and module implementation reduced Linux executable text from
  `170,222 B` to `168,558 B` relative to the pre-extension baseline, while
  static `data+bss` remained `1,936 B`.
- Across the measured runtime workloads, the largest change was `+2.136%`; the
  control workload changed by `-0.228%`. These results show no material runtime
  or resource regression from the newly added syntax support.

The broader V2 comparison remains unchanged: on matched-CPU Linux workloads,
module calls reach up to `3.54x` the MicroPython v1.28.0 Unix minimal result,
Flash is `26.7%` smaller, and static RAM is `88.3%` smaller. See the
[performance overview](../../README.md#v2-性能与资源改进) for measurement scope.

## Validation

- The Linux runtime suite passed `611/611` tests.
- Six Valgrind runners passed with no memory errors and no reported leaks.
- CPython differential checks cover the migrated module combinations.
- The common module template verifies dependency installation, configurable
  `bootEntry`, build, execution, and non-selected entry isolation.
- Linux remains the semantic and performance reference; STM32/QEMU templates
  validate embedded build, startup, resource, and recovery behavior.

## Known Issues

- PikaPython v2 remains a release candidate; APIs and project configuration may
  still change before `2.0.0`.
- Thread-backed concurrency and lock APIs are not included in this release.
  `eventloop` provides cooperative scheduling without thread support.
- CPython compatibility applies to the documented embedded subset and bundled
  module contracts, not the complete CPython standard library.
- QEMU results are not used as performance measurements.

Special thanks to all contributors and users who reported compatibility,
runtime, module, and embedded-system issues.
